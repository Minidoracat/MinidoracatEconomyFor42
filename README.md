# Minidoracat Economy for B42

提供雙貨幣、系統商店、玩家市場、拍賣、獎勵與管理查帳的 Project Zomboid Build 42 經濟系統。

**多人 dedicated server 專用，不支援單人或遊戲內 Host／co-op。** 適用 Build 42.20.4；需搭配 Minidoracat UI Library。

## 發布狀態與功能

已建立 Steam Workshop 項目（ID：3801482125）。以下為已實作功能，不代表所有外部服務已部署；本機驗證與實機驗收的範圍分開記錄。

- 雙貨幣錢包、自訂貨幣名稱與圖示、可用餘額及拍賣保留款。
- 系統商店售出／收購、分幣價格、每日／每人永久限購與收購額度。
- 共用中央市場、拍賣出價及信箱交付；可上架物品受白名單與狀態限制。
- 每日在線獎勵、生存里程碑、以本季最長單命排名的生存賽季與資產榜。
- 管理角色授權、帳戶調整／凍結、金流與稽核查詢、資產對帳。
- 機台與貓娘兩種終端；交易站可選擇啟用原生電台中繼。
- 外部 companion 提供存檔確認、查帳 API 與唯讀日報。Discord 積分存入需另外對接外部積分服務與帳號綁定，不是訂閱即用。

## 安裝

- Steam Workshop：[Minidoracat Economy for B42](https://steamcommunity.com/sharedfiles/filedetails/?id=3801482125)
- 必要依賴：[Minidoracat UI Library for B42](https://steamcommunity.com/sharedfiles/filedetails/?id=3789836701)，**API rev ≥6**。只核對 `0.5.0` 版號不夠，需確認實際 API 修訂；伺服器與客戶端都要使用相容版本。
- 手動安裝：將 `MOD/MinidoracatEconomyFor42/Contents/mods/MinidoracatEconomyFor42` 整個資料夾複製至遊戲使用者資料的 `mods/`，保留其 `42/` 子目錄；UI 函式庫也需安裝。
- 服主在 dedicated server 啟用 `MinidoracatUIFor42` 與 `MinidoracatEconomyFor42`，依賴先載入；Workshop ID 分別為 `3789836701` 與 `3801482125`。
- 伺服器與客戶端更新後同版完整重啟。地圖原生落地式／壁掛式 ATM 預設可在同層 2 格內直接使用，無須管理員登錄；右鍵有「使用經濟終端」。管理員可在「**經濟管理台 → 設定 → 一般**」調整「**原生 ATM 可作為終端**」（預設開啟）與「**允許玩家拆除原生 ATM**」（預設關閉）。兩者獨立、變更即時同步；關閉使用不會解除防拆。重設會清除面板覆寫、回到伺服器沙盒值；面板覆寫須隨世界存檔保存，未存檔崩潰仍可能回滾。自建機台／貓娘終端與一般終端機櫃仍須管理員登錄，不受這兩個選項影響；原生 ATM 不會自動生成電台，第三方不同貼圖不憑外觀猜測支援。
- **原生 ATM 防拆**：未開放玩家拆除時，一般玩家不能用大錘或家具拆解移除支援的四種原生 ATM，伺服器在實際完成動作時再檢查當下設定與權限。列於 `AdminRoles` 且具有原生 `AddItem` 能力的管理員仍可使用原生拆除操作；開放玩家拆除只解除本 MOD 的限制，不略過遊戲原有條件，也不讓 ATM 變成可搬移或旋轉。保護不涵蓋火災／爆炸、其他 MOD 直接刪除或修改客戶端繞過正常操作；不是所有破壞方式的保證。不重置區塊，也不補回已遭拆除的 ATM。
- 服主另行部署 `companion/`（Node ≥24），使用相同伺服器資料目錄提供保存水位確認；**Workshop 不會自動安裝或啟動 companion**。未提供確認水位時，部分待確認轉移會保留並可能達到保護上限，不應忽略。
- 基本遊戲交易不要求 Discord；積分兌換需要服主接入外部服務。日報可獨立手動執行，若要每日自動產生，再由服主安裝主機排程，見下方說明。
- **首次商店目錄**：沒有 `catalog.json` 時建立 13 項預設商品；斧頭全服每日 1 份、抗生素全服每日 2 份（各份 1 件），其他商品維持每人限購。全服額度由所有玩家共用，沒有額外的每人上限。既有目錄不會被更新覆蓋；既有伺服器請在管理台將這兩項的限購方式改為「全服」，並依活躍人數調整份數。價格與收購預設不變。

## 玩家介面

- **浮動入口位置**：拖曳放開後立即保存，每種解析度各自記憶；重生與重新進入時還原，位置還原不會強制開啟已隱藏的入口。
- 經濟中心與管理台都能從標題列切換「圖示＋文字」或窄圖示導覽。兩個視窗分別記住偏好；切換不重新查詢、不放棄草稿，完整名稱仍可從提示與鍵盤焦點讀取。
- 玩家視窗的新預設約占螢幕寬度 84%、高度 86%。已儲存的自訂大小不會被覆蓋；按「重設大小」才套用新預設並置中。
- **固定玩家 ID**：各分頁頂端顯示登入帳號，不是角色名；切頁與捲動不會藏起。點擊或以 Tab／Enter 開啟完整帳號，可複製後提供給管理員。長帳號保留全文入口，讀不到身分時明示讀取中，不猜測名稱。
- **錢包**：對帳單可搜尋說明、對象、物品名稱／代碼與交易編號，並與類型、日期及排序一起使用。搜尋只涵蓋目前已載入紀錄：最近最多 20 筆，月份查詢最多 200 筆；不是搜尋全部歷史。小視窗會把篩選集中到「篩選」。按「餘額詳情」可閱讀與複製完整貨幣資訊。
- **每日在線獎勵**：伺服器可設定每日領取次數與兩次領取的在線間隔。第一次仍須滿足首領在線時間，領取成功後才開始累計下一次；離線不累加，重新登入或換角色不重置當日次數。頁面顯示已領／剩餘次數、還需在線多久與下一次現實換日時間；停用、凍結、上限不足會說明原因。
- **詳情與操作分開**：商店、市場、我的刊登、拍賣、對帳單與信箱，點列立即展開共用浮動詳情，不會直接購買、取消或出價，也不會因滑鼠離開而自動收合。詳情可移動、縮放、捲動與複製全文，不占用清單高度；關閉再開、換列或換來源視窗都沿用調整後的位置與大小，正常儲存介面配置後下次登入仍保留，螢幕變小只移回可見範圍。背景刷新不會把閱讀對象換成另一列；切頁、關閉來源或失去權限會關閉詳情。
- **市場紀錄搜尋**：可搜尋物品、交易對象與原因；先搜尋目前載入的紀錄，再分頁顯示。這是最多 200 筆的已載入資料；回覆被截斷時會標明限制，不會把未載入的舊紀錄冒充沒有結果。
- **交易幣別**：商店可按商品設定倖存幣、貓幣的售價與收購價，每次交易只使用所選幣別；未報價不是免費。市場與拍賣在建立時固定幣別，後續購買、出價、退款與成交沿用該筆紀錄，不自動換幣。「全部幣別」可混合瀏覽，但須先選定一種幣別才能按價格排序。
- **持有排行榜**：依所選幣別的可用加保留金額排名，包含離線玩家；同額同名次。伺服器可關閉公開榜，預設只讓玩家看到自己的精確金額，公開其他玩家金額需由管理員啟用。讀取失敗不會偽造空榜；逾時保留舊榜並標示過期，伺服器拒絕公開時立即清除舊榜。
- **生存排行榜**：在排行榜切換「生存」，可選「目前賽季」或已結束的季別。以本季最長單命的已記錄生存時間排名，不把死亡後多條命加總；同分鐘同名次。死亡保留最佳成績，換季不把前季天數帶入新季。榜單說明、季別日期及長錯誤可從「詳細內容」完整閱讀；資產榜仍是即時餘額，不提供歷季資產快照。
- **本季里程碑**：依伺服器確認的本季單命生存時間達標，自動發放，每個帳號每季每個里程碑一次。新季重新計時，老角色不能立即重領前季已達門檻。初次導入開始記錄時保留既有已領標記，不補造先前成績；該季標為紀錄不完整。生存時間使用遊戲日，賽季期限使用現實時間。
- **本季還有多久**：獎勵頁分開顯示本季剩餘現實天數／截止時間，以及使用遊戲時間的生存進度。管理員調整季期後在線玩家立即更新；手動季、期限未知與到期待伺服器處理各自說明，不冒充剩餘零天。
- **精確搜尋賣家**：市場與拍賣的瀏覽頁可輸入部分名稱，從候選選取完整帳號；候選包含離線但仍有有效刊登的賣家，不公開私人帳本帳號。選定後按完整帳號篩選，與物品關鍵字分開；可清除賣家條件，排序與翻頁仍保留所選賣家。
- **信箱領取**：每列有「領取」，上方可「領取全部」。批量以開始時選定的待領信件逐封處理，整封放不下就留下並繼續後面的信，不會順帶領走新到的郵件。通知只列本次實際發生的已領取、保留及失敗結果，不顯示零項目。託管用量包含未領信件、自己的刊登及拍賣，介面會分別列出構成。
- **信件賣家**：新市場購買與拍賣得標的信件會顯示來源種類及賣家帳號，完整資訊也可查閱；部分交付後仍保留。舊信缺資料就不推測補填，系統商店與退件不會假造第三方賣家。
- **交付異常**：正常領取不拆封；若交付途中發生例外且部分物品無法回收，僅將實際確認的件數登記為已交付，其餘仍可從原信件領取。結果會明示件數，不把重新登入或死亡當成整封已完成的證明。
- **貨幣與讀取狀態**：右上圖示放大至 48px，保留款與餘額採相同字級；滑鼠移到貨幣區塊可讀完整名稱。歷史讀取失敗會標示舊資料並提供「重試」，浮動詳情保留完整錯誤說明。
- **購買與取消**：購買前顯示重量與可容納量的預估，負重與背包容納上限分開說明；需要寄存時另行確認，伺服器在付款前再檢查。取消刊登／拍賣會先退件並立即嘗試交還，有空間就進主背包，放不下才留信箱；刊登費不退。
- **費用與規則**：市場與拍賣的成交稅、刊登費說明統一放在標題下方、搜尋列上方，長文字會換行。上方「費用與規則」可用滑鼠或鍵盤開啟完整內容；窄窗不會為了說明擠掉清單與頁碼，已開啟的全文會跟隨新費率更新。
- **鍵盤**：Tab／Shift+Tab 切換區域，方向鍵選列或切換同組按鈕；紀錄列按 Enter 開啟詳情，Esc 先關閉詳情再處理來源視窗。唯讀內容可用 Home／End 捲動、Ctrl+C 複製，也有「複製全部」與「關閉」。透明度與通知秒數位於側欄「設定」，保留滑鼠滑條與鍵盤加減操作。交易確認開啟時，後方清單、捷徑與通知泡均不能操作。

## 管理操作

僅支援多人專用伺服器。更新本次介面後，伺服器與客戶端都需要重新啟動。

- 在經濟中心按「管理」，開啟獨立的「經濟管理台」。視窗會記住位置與大小；再次開啟會帶到前景，不會建立第二份管理介面。
- **管理限制與角色授權**：「設定 → 管理限制」可調整單筆、個人每日及全服每日調帳上限，並設定可寫入、唯讀與自行調帳的角色。修改這六項需要原生「角色管理」權限（`Capability.RolesWrite`）；只有經濟管理權不夠。原生角色管理者即使不在經濟角色名單內，仍能進入面板修正名單，但不因此取得調帳等一般寫入權。
- **從現有角色選取**：三份授權名單使用伺服器的原生角色清單，可逐一加入或移除，包含自訂角色；保留完整名稱與大小寫，不必手輸入或拼分隔符。空集合表示不授權任何角色；已不存在的角色會標示，須明確移除。讀不到原生清單時不能儲存；Esc 先收起下拉，再關閉編輯。設定即時生效並記錄稽核，耐久性沿用世界存檔，未存檔崩潰可能回滾。
- **調整自己的餘額**：預設不授權。將自己的角色同時列入「可寫入的管理角色」與「可調整自己餘額的角色」後，可在「玩家 → 單一帳戶操作」查詢自己的登入帳號再調帳；仍須填原因、比對錢包版本，並套用同一套單筆、每日、全服上限及稽核。不能凍結自己的帳戶；撤權會關閉相關編輯並取消尚未送出的操作。
- **賽季管理**：「管理 → 賽季」可查看本季開始、預定截止、歷季實際結束日期與已記錄人數。具有原生角色管理權的人可設定「賽季長度（現實天數）」或填理由確認「開始下一季」；一般經濟管理／唯讀角色只能查看。手動換季封存舊季成績，不清除餘額、每日在線獎勵或遊戲角色。
- **現實天數與停機**：一天為 24 小時。修改長度立即從本季原開始時間重算截止日，不重開賽季、不重設生存成績或已領標記；`0` 改為手動，不再倒數。設為 30 天是整季共 30 天，不是在現在追加 30 天。會使本季立即過期的縮短會被拒絕；要立即結束請明確「開始下一季」。停服期間照計時；逾期重啟時只結束舊季一次，新季從重新執行時起算，不補造多個空季，舊季截止日與實際結束日都保留。
- **紀錄界線**：歷季成績不自動刪除，保存每帳號該季最長單命，不保存逐秒紀錄。只有伺服器能確認的存活時間才計入；讀取失敗不冒充零或空榜。賽季資料與餘額同樣隨世界存檔保存，未存檔崩潰仍可能回滾；既有備份與還原由服主負責。換季逾時不自動重送，取消尚未送出的操作、關窗或失權都不會在稍後偷偷執行。
- **商店與限購**：可選「每日每人」、「每日全服」或「每人永久」三種互斥模式，以商品份數計數，跨幣別購買共用份數用量；上限 `0` 表示不限購。每日模式的重置日期與倒數採現實時間，依玩家時區顯示。每份件數與商品分類建立後仍可單筆或批量編輯，不重算已購份數、不改既有信件，也不自動換算每份價格。Ctrl 加選、Shift 選範圍，選取兩項以上即切換批量表單；每幣有獨立的售價、收購價與方向開關，只套用明確修改的欄位，未動欄位保留各商品原值，零與關閉也是有效值。混合初始值不會被當成零，已有草稿時改變選取先確認；窄窗可捲動，Tab 會將下一個欄位帶入可見範圍。
- **永久限購的起算與保存**：從支援此功能的版本首次載入世界起，所有成功購買（包括每日模式及不限購商品）皆按登入帳號與商品 ID 累計，不追補舊交易。死亡、換角色、換季、切換限購模式、改價或停售再開都不清零；降低上限至已購份數以下時停止新購買，不追回既有物品。已付款寄存在信箱的購買照樣占用額度，領取不再計一次。使用相同商品 ID 會保留累計，新 ID 視為另一商品；不提供人工清零。計數隨世界存檔保存，崩潰或還原備份仍可能回滾，並非跨世界的永久紀錄。
- **購買 JSON 紀錄**：沿用 `Lua/MinidoracatEconomy/events-YYYYMMDD.json` 的逐行 JSON。新增的 `shop.purchase` 紀錄包含當次限購模式、上限、成交後已用份數及帳號永久累計；欄位見主規格「階段 C：系統商店售出」。舊行不改寫，JSON 不是另一份限購計數來源，查帳時仍須辨識回滾與存檔確認；寫檔佇列或磁碟失敗可能造成缺漏，不能把缺紀錄當成沒買過。
- **商品編輯版面**：基本資料、限購份數、各幣報價與收購狀態依固定順序排列。寬度足夠時欄位並排、每幣一列；空間不足改用完整編輯區，按「回到清單」再選商品。一般規則可從「商品資訊」完整閱讀，批改會保留目標與本次異動摘要；內容增長不會打斷正在輸入的欄位。
- **收購狀態與額度**：設定上限與今日剩餘分開顯示；總開關關閉不代表設定被改為零。總開關開啟後才分辨幣別不能交易、真實零上限與今日額度用完，未提供的資料保持未知。
- **商品分類篩選**：以原生下拉選擇商店分類，並可搭配搜尋；既有自訂分類也能選取。商品分類只影響商店篩選，不會修改原物品分類。批改期間不允許切換篩選範圍。
- **玩家資產列表**：玩家頁提供「帳號列表」與單一帳戶操作兩種模式，列出經濟系統已知的在線、離線及零餘額玩家；可按狀態、帳號或幣別總持有篩選及排序，再分頁顯示。點帳號進入既有查帳／操作流程，返回時保留篩選；儀表板與貨幣頁的「查看持有人」會跳到同一份列表。
- **統計口徑**：總持有＝玩家可用餘額＋拍賣保留款，與系統帳戶分開計算；守恆差額為全體分錄的核對值，不是營收。每帳戶上限限制可用餘額，並不存在全服流通總量上限。舊統計缺漏與無法讀取的錢包會明示不完整，不補成零或冒稱完整排名。
- **商品紀錄捷徑**：銷售／收購紀錄會搜尋右側目前顯示的既有商品，使用物品代碼跨同物品的不同商品項目查詢；同時清除先前不相關的日期、貨幣與帳戶類別。左側搜尋濾空不會丟掉右側商品上下文；尚未選取或正在新增商品時，則查看該類全部商品。未儲存草稿仍先確認，不會直接丟棄。
- **玩家收據與金流**：帳號狀態區集中提供「玩家金流」入口，收據列只開單筆詳情，不再重複放玩家金流按鈕。金流頁的玩家候選與物品選擇為精確條件，另有獨立的關鍵字「包含／完全相同」搜尋；符合條件的交易仍保留全部帳戶與幣別。
- **刊登與拍賣查詢**：玩家狀態顯示目前刊登、拍賣數量與上限，並有各自捷徑。管理清單與玩家端共用輸入關鍵字即列候選的賣家選擇器；選完整帳號才精確篩選。每列「此賣家」會清除舊條件、回到第 1 頁，查看該帳號全部有效刊登或拍賣；不會把相似帳號一起算入。
- **多語名稱搜尋**：以目前語系、物品代碼及真實英文名稱搜尋，本體英文由隨附字典提供，MOD 英文則於載入時讀取。若 MOD 同時提供被版本目錄遮蔽的共用英文字典，或來源讀取失敗，仍保留可用搜尋並列出缺漏來源；查無結果不代表完整查證沒有交易。一次名稱查詢超過 256 種物品時必須縮小條件。
- **稽核全文與管理員篩選**：選取摘要後按紀錄位置讀取完整原因，缺檔、讀取失敗或舊紀錄定位有歧義都會明示；不把截短摘要當成全文。管理員候選來自所查區間的歷史紀錄，包含離任帳號，選取後依帳號精確篩選；切換條件不混用舊快照。日期範圍上限是單次查詢跨度，不是舊資料的可讀年齡。
- **狀態與貨幣預覽**：已上架／已啟用為綠色、停用為中性灰、被總開關暫停為橘色，並保留文字與原因。貨幣設定可查看目前總持有、可用、保留與持有人數，並預覽生效圖案；修改名稱後，各交易與排行榜下拉選單會更新名稱而保留所選幣別。
- **錢包版本**：帳戶摘要的 `v13`、`v17` 是各帳號、各幣別獨立的資料修訂號，不是 MOD 版本或玩家等級。每筆有效分錄更新可用／保留金額時遞增；一次交易可能有多筆分錄，因此不是交易總次數。管理員調帳會比對此值，避免拿過期餘額進行調整。
- **大字級與完整數值**：帳號貨幣摘要可捲動，點選幣別可複製完整餘額；帳號狀態、系統狀態、貨幣設定及整合詳情各有可捲讀框，不再因卡片太矮省略最後幾行。欄位中的省略文字不會截掉完整詳情；系統檔案錯誤、兌換限制、整合發行／回收額度都能讀到全文。
- **窄視窗篩選**：金流的「篩選」面板可捲動，返回結果、重試及清除按鈕保留在可視範圍。市場與拍賣紀錄在空間不足時分開顯示篩選與結果；種類過多可用左右鈕查看，原有多選保留。設定列依字級與數值預留控制空間；點選名稱區可開啟完整的唯讀說明，唯讀管理員不會因此取得寫入權限。
- **新增與再次編輯商品**：按「新增商品」，以譯名、原文或物品代碼搜尋目前載入的物品（含 MOD）。選取後設定商品 ID、每份件數、分類及各幣價格；新商品預設不收購。既有商品的 ID 與物品種類不可更換，每份件數與分類可明確修改；名稱、原文、物品代碼、商品 ID 與每份件數保留在編輯上下文，完整報價與長錯誤可開啟詳情閱讀。
- **收購總開關與額度**：「已啟用／已停用」表示目前狀態，「開啟收購／關閉收購」才是操作。總開關停用時，商品設定仍保留但不會成交。幣量額度按幣別與帳戶／全服分開，商品收購份數跨幣共用；任一幣量額度為 0 即停止該幣收購，不代表不限。貓幣收購額度預設為 0，需由管理員明確開放。
- **白名單**：「分類規則」管理可上架分類；方向鍵只選列，Enter／Space 切換核取狀態。「指定物品規則」提供允許、排除或依分類，搜尋只找已設定規則，其他物品以「新增物品規則」尋找；失去物品資料的舊規則也可移除。
- **不同清單互不連動**：商店商品由 `catalog.json` 管理，市場白名單由 `whitelist.json` 管理；新增商店商品不會自動放寬玩家市場的上架規則。商店上限為 200 項，停用商品不會釋放名額。
- **尚未套用的編輯**：離開商品編輯區前會詢問是否放棄。儲存失敗或收到新目錄時，草稿會保留；若目錄版本已變動，取消編輯可採用最新收到的資料，再重新修改，避免覆蓋其他管理員的變更。
- **價目與既有交易**：整批價目一起驗證，發現不合法欄位或可循環套利的設定時整筆拒絕，不部分寫入。舊格式目錄會在載入時正規化；新編輯一律使用分幣價目。重送已完成的相同操作會回覆原結果，之後的停用、價格範圍或商品目錄變更不會改寫過去結果；更換確認內容則視為衝突。拍賣原有保留款在幣別停用或調低上限後仍可正常釋回，不當作新發行。
- **鍵盤與完整資訊**：管理商店、白名單與市場可用 Tab、方向鍵、Enter、Esc 操作。物品名稱及紀錄原文可在共用浮動詳情捲動閱讀與複製；背包選物網格支援上下左右選取。
- **調帳對話框**：滑鼠點入金額後可用 Tab／Shift+Tab 切換輸入欄，方向鍵切換幣別按鈕，Enter 選擇或確認；警告內容可用鍵盤閱讀，Esc 不會把操作傳到後方頁面。

## 交易站電台

1. 管理員建造經濟終端後，右鍵選「登錄為交易站（含市場電台）」。若已登錄為 ATM，先移除終端登錄，再登錄為交易站；不必重建終端造型。
2. 在「經濟管理台 → 設定 → 市場電台」開啟「交易站語音收音」。**預設關閉**，升級不會自動啟用麥克風轉播。啟用後，貓娘終端肩側／機台上緣會出現小喇叭；它仍是同格的原生電台，不再露出大型 HAM 機身。
3. 玩家右鍵交易站的「交易站電台與收音說明」，可開啟能捲動、複製、用 Esc 關閉的完整說明。內容是開啟時最近收到的狀態快照；重新開啟可查看最新狀態，不代表遠方已聽到聲音。
4. 在任一使用原生電台介面的收音機／對講機／世界電台，或車內的車用電台，開機後從預設清單選「**市場電台**」，再按「**調整頻道／調諧**」。不必手動新增頻道；共用項直接使用伺服器的精確頻率，原本的 101.1 MHz 也能調入，不經 0.2 MHz 滑桿。

- **兩個獨立開關**：`RadioRelayEnabled` 控制玩家語音／一般聊天中繼；`RadioIntervalMinutes=0` 只停止行情文字摘要。ATM 兩者都不提供。
- **全機共用預設**：這是原生選單的固定共用項，不逐件寫入物品的 `DevicePresets`；已有十個玩家預設也不占名額、不覆蓋原名或頻率。共用項不能在單台編輯／刪除，普通預設照常操作。伺服器變更頻率後清單會更新，但不自動切換正在收聽的頻道；仍須明確按調頻。裝置頻段不支援時不提供假選項，電視與純媒體播放器不受影響。
- **同頻收發**：共用 `RadioFrequency`（預設 `101100`＝101.1 MHz）與 `RadioRange`。有限範圍以發送端為準，回程另受對方裝置範圍限制；`0` 表示全地圖，原生裝置使用 100000 格涵蓋電台座標範圍，不將文字廣播的 `-1` 寫入裝置。
- **原生限制保留**：語音要求伺服器 `VoiceEnable`，並依玩家 PTT／VAD 設定。附近與下方樓層的裝置可能被本體納入，不能當私聊；一般聊天優先使用背包內已開機的雙向電台，`/all` 與私訊不由此轉播。收聽者需有開機、非零音量、同頻的裝置。
- **管理與狀態**：一般搬移、拆解、旋轉、電池與媒體動作會拒絕這台伺服器管理的電台，普通收音機不受影響。原生封包不提供完整防攻擊鎖，異常關機採限頻率恢復；顯示同步失敗時，舊裝置狀態仍可能存在，請查伺服器記錄。
- **存檔與卸載**：喇叭底層仍是原生世界物件，終端登錄與設定隨世界存檔保存；舊版自有 HAM 在載入或同步時換成小喇叭，玩家自己放的 HAM 不變，不必重建終端。移除本 MOD 前，先在各交易站區域載入時解除登錄、確認小喇叭已移除，再正常存檔；停用 MOD 本身不會執行清理程式。
- **驗收界線**：使用者已確認交易站麥克風實測可用；此結果不擴大為所有一般聊天、距離、回程或不同伺服器配置均已驗收。裝置資料、原生操作及離線介面另有驗證，離線繪圖不是遊戲截圖。使用本功能時，伺服器與客戶端須同版重啟。

## 存檔確認與待對帳

- 領取後重新刊登、拍賣或出售會保留每件物品的來源與轉移紀錄。舊版物品仍能與世界中的原始信件及份數對應時，伺服器會補上逐件識別；來源已回滾、已清除或無法確認時，每封來源信列為一筆待對帳，不猜測補發或刪除。
- **拒絕原因**：刊登、建立拍賣或出售遇到來源問題時，交易確認會列出受影響的物品、來源信件／交易、目前判斷與下一步。「來源無法確認」不等於物品代碼損壞或商品目錄設定錯誤；可自行完成的領取、等待世界存檔確認與需要管理員核對會分開提示。
- **自動對帳的界線**：仍有可確認原始信件與空位的舊物品，重新轉出時也會嘗試補齊識別。若來源信件的建立、領取與後續轉出全部已證明回滾，而且來源鏈已不存在，重新核對會自動清除失效的待處理狀態，不補發物品或退款。只有領取回滾、來源仍存在或證據不足時不會自動作廢。
- **伺服器恢復紀錄**：完成物品轉出時會寫入獨立的伺服器紀錄，恢復與人工預覽以該紀錄及最新處置為準，保留完整物品資料。查證採分段讀取；尚未讀完、讀取失敗或證據矛盾時保留待處理，不冒稱恢復成功。查證期間移走的物品仍視為存在，請按提示放回背包再重新檢查。
- **人工恢復與缺證據**：有可信紀錄時只補回仍需交還的部分，已在手或由其他來源持有的物品不重複發放。完全缺少伺服器紀錄時，管理員須明確接受玩家提供的資料，查看完整預覽後才可退物或不補發；這類處置不發幣，並在稽核標明來源未經證明。損壞、無法讀取或屬於其他帳戶的證據不能用此選項略過；先修復來源再重新檢查。
- 請讓既有 companion 與遊戲伺服器使用同一個資料目錄。它解析完整且穩定的世界存檔後，自動發布本次存檔確認；遊戲端只接受相同世界與本次啟動的有效水位，不以主控台的存檔完成訊息或經過多久替代證據，也不要求額外強制存檔。
- companion 未執行、確認檔失效或尚未存檔時，等候世界存檔確認的轉移紀錄不會自動刪除。達保護上限會暫停新增物品移動並顯示提示；管理員應檢查 companion、正常世界存檔及「系統」頁的存檔確認狀態，不要手動清除待對帳紀錄。
- **全服總覽**：直接開啟「管理 → 資產對帳」，不必先查玩家。全服已知待對帳紀錄依帳號分頁，搜尋只篩選紀錄，不改變全服摘要；離線或讀取失敗的帳號不會被當成沒有紀錄。按「狀態快照」可閱讀與複製完整摘要、存檔確認、各帳號待對帳／待確認轉出筆數，包含只有待確認轉出而沒有待對帳列的帳號；離線的待確認轉出數量標為未知。玩家頁原有「待對帳」快捷會切到同一分頁的單帳號檢視，可返回全服。
- **批次重新檢查**：「重新檢查全服」會對總覽列出的在線帳號逐一重新核對，離線帳號明示略過。它只執行既有可證明的自動對帳，不等於全部補發或刪除；可停止尚未送出的項目。
- **多選與批次處置**：一般點列讀詳情；Ctrl＋點列切換單筆選取，Shift＋點列依目前清單增選連續範圍，也可使用「選取本頁」。選取跨頁／搜尋保留，範圍錨點不跨到另一頁或另一個搜尋。各處置顯示符合的筆數，按下後只處理選取集合中符合該操作的紀錄；其餘不修改並保留選取。同一筆可同時具有補回／不補發選項，仍由管理員選擇其中一種，不會自動執行兩種。
- **批次確認與結果**：確認前列出選取總筆數、本次處理筆數與不處理筆數，完整列出本次目標及實際件數，必填理由套用到每筆。伺服器仍逐筆重驗版本、權限與實際資產；版本改變需重新核對。逐筆結果保留成功、已結案、部分完成、拒絕、未送出與未知，另列出本次不適用而保留的筆數，不把混合選取冒充全部完成。
- **停止與逾時**：停止、切頁、隱藏或失權會取消尚未真正傳送的項目；已傳送但未收到回覆的項目可能已完成，標為結果未知，不自動重送。恢復權限或重新開窗不會續跑原批次；請查看逐筆結果並重新檢查後再決定。唯讀角色可看總覽、快照與選取，不能處置。
- **逐筆處置**：只顯示伺服器當下允許的操作，每次必填理由並確認。已回滾來源可回收，裝備／熱鍵掛載物品需先卸下，容器需先清空。來源缺證據的現物可由管理員核對歷史後明確承認；這不是伺服器證明，也不會發物或發幣。部分失敗不結案，證據改變會要求重看。
- **舊轉出補償**：只有已證明回滾、全數原件不在、識別與數量一致的舊刊登／拍賣，才可由管理員確認後依原快照補回信箱，不重新上架。系統收購不提供退物補償。作廢與補償都留下世界端紀錄；在世界存檔前仍保留待處理證據，若世界回滾，需重新人工核對，不能視為已永久定案。
- **新版仍可能待對帳嗎？** 正常的新領取、刊登、拍賣及收購會保留逐件來源，不再產生舊版只記物品編號的轉出／領取格式；但舊物品、舊角色與還原舊存檔仍可能帶回遺留資料。新版遇到來源證據不足、重複識別或讀取／回收失敗，仍會保留待對帳以防誤補發、誤刪；`missing` 則是本次世界存檔確認缺失，不會因更新版本就變成已確認。
- 世界存檔間隔為 0 代表未排程定期世界存檔；玩家背包存檔不能代替世界存檔。服主應自行設定合適間隔並正常關服；本 MOD 不自動改伺服器設定，也不額外強制存檔。

## Companion 唯讀日報

日報是外部的一次性指令，不需要管理員進遊戲，也不要求常駐 companion HTTP 服務正在執行。它只讀取經濟事件、啟動紀錄及世界存檔，產生數值對帳結果；不寫遊戲資料、不呼叫 AI、不補款或自動修復帳目。

在 `companion/` 目錄安裝開發依賴，將 `.env.example` 複製為 `.env`，再依環境設定：

```dotenv
ZOMBOID_DIR=
SERVER_NAME=servertest
REPORT_TIME_ZONE=Asia/Taipei
REPORT_OUTPUT_DIR=./reports
```

`ZOMBOID_DIR` 留空使用目前使用者的 `Zomboid` 目錄；正式環境請指向要分析的伺服器資料。Node ≥24 原生載入 `.env`，已設定的程序環境變數優先；實際 `.env` 不進版控。

```bash
cd companion
npm install
npm run report                       # 指定時區的前一天
npm run report -- --date 2026-09-13  # 手動指定日期
npm run report -- --help
```

- **日界線**：預設台灣時間午夜至隔天午夜，區間採含起點、不含終點；報告寫明時區與 UTC 起訖時間。夏令時間依 IANA 時區處理，不假設每天固定 24 小時。跨日會讀到相鄰的 UTC 事件檔；少數歷史時區的跨日回撥會讓一天不連續，此時明確拒絕，請改用 UTC 與另一個輸出目錄，不會錯分交易。
- **輸出**：`REPORT_OUTPUT_DIR` 相對執行時工作目錄，預設 `companion/reports/`。每個日期有同名 JSON 與繁中 Markdown；JSON 保留所有可解析的當日交易與來源位置，Markdown 顯示分幣金流、交易種類、管理員調帳與異常摘要。大量明細只在 Markdown 預覽前 100 筆，完整資料仍在 JSON。
- **數值語意**：已保存、已回滾、待確認與證據不足分開。只合計有效且已保存的交易，檢查分錄平衡、可用／保留款前後值、跨交易餘額鏈及存檔錢包；保留款搬移不當成新發幣。流入／流出是玩家側分錄流量，不是商店營收；超出可精確輸出的整數範圍時，金額為 `null`／「—」，不可當成零。
- **延後確認**：同一輸出目錄內，先前仍有待確認、未知或資料不完整的日期會用本次來源重新計算，更正列入本次日報。重跑同一天保留既有更正，不重複計入；若舊交易已從來源消失，停止並保留既有報告，不以空資料覆蓋。
- **資料限制**：缺檔、壞 JSON／UTF-8、未完成行、不穩定存檔及不明啟動順序均明示。缺日檔也可能只是那天沒有活動，但無法據此證明零交易。讀取上限沿用 `MAX_EVENTS_IN_MEMORY`（預設 200000 筆非空事件），達上限不能視為完整；可依保留量調整此值。沒有憑證的歷史不猜已保存，也不把異常直接判定為作弊。
- **資料安全**：報告包含玩家帳號、管理操作及原因，請限制檔案存取權限，外送 AI 前自行確認資料範圍。預設報告目錄已忽略；自訂輸出請放在 repo 外或另行加入忽略規則。同一目錄不能混用其他來源、世界或時區，已知世界也不能被暫時未知的來源覆寫。每檔原子替換，先完成 Markdown、最後提交含其摘要的 JSON；兩檔不是跨檔交易，失敗回非零碼，重跑會檢查配對並重建損壞／缺失的 Markdown。只有 Markdown、卻遺失 JSON 時會停止，請先恢復 JSON；不要把 Markdown 當另一份帳本。新報告若在兩檔之間遭硬中止，確認沒有日報程序後可移除該次孤立 Markdown，再重跑。
- **排程**：不內建計時器。由服主用 cron、systemd timer 或 Windows 工作排程器每天執行上述指令，工作目錄設為 `companion/`，例如報告時區午夜後幾分鐘。排程器的時區與 `REPORT_TIME_ZONE` 是不同設定，需分別核對；本功能不會自行安裝或改動排程。輸出目錄使用單一執行鎖，異常中止留下 `.report.lock` 時，先確認沒有其他日報程序，才手動移除。

退出碼：`0`＝本次檢查未發現缺漏或對帳線索；`2`＝報告已產生，但有待確認、資料限制或異常；`1`＝設定、來源消失或檔案操作等執行失敗。`0` 不是帳本完整性保證。正常 JSON／Markdown 可交給 AI 解讀；日報不會自動將資料傳到外部服務。

## 開發

玩家介面的程式位於 `42/media/lua/client/MinidoracatEconomy/`，依責任分工：

| 檔案 | 責任 |
|---|---|
| `ECPanel.lua` | 視窗生命週期、控制項組裝、請求狀態與跨頁協調；保留 `C.Panel` 入口 |
| `ECPanelWidgets.lua` | 共用控制項、完整文字閱讀區、資料列格式與清單繪製元件 |
| `ECPanelFilters.lua` | 玩家紀錄的搜尋、類型、日期、排序與本地分頁 |
| `ECPanelDialogs.lua` | 購買、出售、刊登與拍賣的交易確認及背包選物 |
| `ECPanelPreferences.lua` | 透明度、通知秒數及偏好設定面板 |
| `ECPanelLayout.lua` | 視窗尺寸、各頁版面、欄位、詳情區與畫面繪製 |
| `ECDetailWindow.lua` | 玩家與管理頁共用的浮動唯讀詳情、複製與關閉生命週期 |
| `ECLeaderboard.lua` | 公開排行榜、分幣選擇與拒絕／過期狀態 |
| `ECAdminAccounts.lua` | 管理員全玩家列表、篩選、排序與帳戶跳轉 |

伺服器的 `ECStats.lua` 共用帳戶母體與分幣統計；`ECRecoveryJournal.lua` 保存恢復用的權威轉出紀錄並以既有分段讀取器查證，不取代事件／收據帳本，也不提供備份或還原工具。

內部模組不反向載入主檔；視窗仍統一持有控制項及請求狀態，不增加第二套頁面框架。
`uv run scripts/verify_mod.py` 會檢查每個函式的累計 local 預算（≤190），包含所有內層函式。

- `link_workshop.bat`：把 repo 掛載到 `Zomboid\Workshop\` 與 `Zomboid\mods\`（符號連結，repo 改動即時生效）
- `PZ_Test.bat`：啟動測試（客戶端 / 專用伺服器 / 多客戶端組合）

## 發布準備

### 發布與更新檢查

首發項目已由使用者建立，ID 已回填。以下為後續核對清單，不授權自動上傳。

1. 首發版本為 `42.20.4-0.1.0`（2026-09-14），對應 tag `v42.20.4-0.1.0`；後續改動另列下一版本，不覆蓋既有 tag。
2. 先確認 Workshop 訂閱端取得 UI 函式庫 API rev ≥6，再發布 Economy；本機開發版不能代表玩家訂閱到的版本。
3. 在乾淨的 dedicated server／客戶端組合確認首次安裝、權限與基本交易流程；服主確認 companion 保存水位正常。保留已通過的實測，不以離線圖冒充遊戲截圖。
4. 提交要發布的日報與文案改動，通過 MOD 閘門與 companion 測試；確認 `.env`、報告、開發工具狀態及私密資料不在上傳內容內。
5. 執行 `uv run scripts/gen_workshop_txt.py` 同步英文描述，保留既有 `id=3801482125`，不要重新建立 Workshop 項目。
6. 核對 Workshop 的 Required Items 已包含 UI 函式庫。遊戲上傳器使用 `preview.png`；網頁動態封面使用 `workshop/preview.gif`，另以發布腳本的 `preview` 模式更新。
7. 取得明確上傳授權後，依家族流程補齊其他語言描述與動態封面，最後核對公開頁面、依賴及訂閱下載內容。往後更新才使用 `Publish_Workshop.bat`。

### 發布到 Workshop

雙擊 `Publish_Workshop.bat`：先確認 Steam 用戶端已以作者帳號登入（未登入會喚起 Steam 並等你登入後重試），
再選擇更新 MOD 內容（含 `STEAM_CHANGELOG.md` 更新說明）／GIF 封面／簡介／全部；提交後回查 Steam，
任一不符即以非零碼結束。設定在 `scripts/workshop_publish.json`（Workshop ID、簡介語言槽來源、GIF 路徑）。

```
uv run --no-project python -B scripts/publish_workshop.py --mode all --yes       # 自動化／AI；或 content / preview / description
uv run --no-project python -B scripts/publish_workshop.py --mode all --dry-run   # 只檢查、顯示計畫
```

退出碼：`0` 成功／`2` 參數或取消／`3` 未登入、帳號不是擁有者／`4` 前置檢查失敗／`5` 提交失敗／`6` 已提交但回查不符。
網頁動態封面放 `MOD/<資料夾>/workshop/preview.gif`（不在 `Contents/`，不會下載給玩家）；遊戲內上傳器仍用 `preview.png`，
且每次會把網頁封面覆回靜態，需要動態封面時一律改用本工具發布。
